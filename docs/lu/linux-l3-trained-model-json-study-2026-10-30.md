## Strict native Protobuf tool-turn acceptance

A separate real-GGUF acceptance test requires a model-generated `kind=tool` request for `lu_files_read_text`, an authorized native Protobuf file read, then a second model step producing a final response derived from the file data. The test must not substitute scripted tool decisions or treat the first text completion as a tool call.

- Unconstrained SmolLM2 returned a JSON **array** describing available tool metadata instead of a required request object: `model_nonobject_rejected`.
- Unconstrained Qwen3 returned **ordinary text**, not a tool request: `model_text_boundary_rejected`.
- A direct llama.cpp `/completion` experiment showed that host-supplied per-request `json_schema` can constrain a tool-or-final JSON envelope; this is only a **decoding hint**, not tool authorization.
- The experimental Lu adapter now selects a strict, host-owned `oneOf` tool/final JSON envelope when a **native tool turn** calls `generate_json_object`. Ordinary conversational inference continues to use `generate` without a JSON constraint. The original JSON validator, policy/approval gate and Protobuf dispatch authority remain unchanged.
- The experimental Qwen3 strict gate still **FAILED**: after generating schema-valid JSON, it selected `kind=final` on the first step rather than issuing the requested file-read tool. This is a real model-behavior failure, not an acceptable two-step tool-turn.
- **No model-generated file-tool execution or full turn completion is claimed**.

## Security/diagnostics and regression

- Existing `real_gguf_tool_json.rs` failure logging on the Linux base branch was hardened: no raw model text or file-content previews are emitted; only a bounded failure class, byte length and SHA256 of generated bytes.
- Experimental `InferenceBackend::generate_json_object` defaults to **fail closed** for unsupported backends (no fallback to unstructured text). A unit test proves refusal and recovery of host `Ready` phase.
- The constrained envelope is inserted by Lu's host-selected backend behavior, **not** a model-controlled field, and includes no authorization grant.
- New structured API is threaded through `inference_host`, `persistent_llama_backend`, `inference_bridge`, `inference_supervisor`, and the `SupervisorModelStep` host adaptor; deterministic test fakes were updated.
- The exact six locally compiled and tested source files were committed to this **experimental branch**, and all six remote Git blob SHA1 values were checked against the original locally tested bytes.
- Local offline regression: **282 passed, 0 failed, 1 intentionally ignored**; `cargo fmt -- --check` PASS; `cargo clippy --offline --locked --all-targets -- -D warnings` PASS.
