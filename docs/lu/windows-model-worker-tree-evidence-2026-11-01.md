# Lu Windows model-worker descendant cleanup — acceptance harness

Source-only test branch `work/lu-win-model-tree-cleanup-20261101` (2026-11-01). This change does NOT modify the Lu runtime or any previously built NSIS executable.

The earlier Gate 5 UIA harness only checked direct child `llama-server.exe` processes after the Lu parent had exited. If an engine spawns a child that survives and is reparented, a post-exit parent-only query cannot find it. The new test-only Windows code snapshots the **direct Lu-owned engine and all process descendants recursively before Lu exits**, recording only PID and process creation time (never command lines, environment or user paths). After exit it requires each captured process identity to be absent, even if reparented or orphaned. A disposable Windows test uses a renamed local Windows system executable to spawn a supervised parent and one descendant, confirming that live and orphaned descendants fail the exit test. It only kills explicitly captured test fixture processes and runs in an ephemeral Windows runner.

The installed GUI model/tool/restart probe uses this snapshot after it reaches a real model-generated tool turn. The source test is a harness check; full Gate 5 still requires a successful test against an actual built NSIS binary and a separate Windows kill-on-close Job Object if the architecture promises kernel-enforced descendant cleanup. Windows 10/client AMD physical coverage is independently outstanding. This source branch is isolated from Lu alpha installer compilation and Cognitum/Linux experimental work.
